# Внешние интеграции

## Системы

| Система | Тип | Назначение | Доступ | Основание |
|---|---|---|---|---|
| Telegram MTProto | API | Команды, группа/тема, личная и прямая отправка | `API_ID`, `API_HASH`, файл сессии | `main.py`, `control.py`, `scheduler.py` |
| SQLite | локальная БД | Напоминания и очередь отчётов | локальный файл | `db.py`, `config.py` |
| systemd | менеджер процесса | Перезапуск на Raspberry Pi | unit-файл | `deploy/tgreminder.service` |

## Хранилища

- `reminders.db`: таблицы `reminders` и `notices`; схема создаётся в `db.connect`.
- `reminder.session`: авторизация личного аккаунта; исключён из Git.
- `scheduled_msg_id` остаётся только для миграции старых запланированных сообщений.

## Секреты и доступ

- `config.py` загружает `.env`; обязательны `API_ID` и `API_HASH`.
- `.gitignore` исключает `.env`, сессию и базу. Ротация ключей не описана `[TODO]`.
- Обработчик принимает команды только от своего аккаунта в найденной теме (`main.py`, `control.py`).

## Отказы и наблюдаемость

- Планировщик проверяет связь через запрос Telethon; после восстановления сообщает о перерыве.
- Отчёты о пропусках и ошибках хранятся до успешной отправки в `notices`.
- Прямая отправка повторяется через 5 минут после ошибки; при `FloodWait` выдерживается срок Telegram.
- Метрик и трассировки нет; логи пишутся через стандартный `logging`.
