# Архитектура

## Стиль и ограничения

- Один процесс asyncio содержит Telegram-клиент, обработчик команд и планировщик; один SQLite-файл хранит состояние.
- Новые сообщения никому не ставятся в серверный планировщик Telegram. Отправка происходит из процесса по локальным часам.
- Указанная группа и тема определяются при запуске по точным именам. Проект рассчитан на один экземпляр.

## Поток данных

```text
Команда в теме → main.on_command → commands.handle → db.add_reminder
→ scheduler_loop → личная тема или адресат → db.advance
```

1. `control.find_control_topic` находит группу и тему, после чего `main.py` слушает только собственные сообщения в этой теме.
2. `commands.py` принимает `напомни`/`напиши`, время, интервалы и адресата; ошибка формата возвращается в тему.
3. `db.py` хранит следующую отправку и число оставшихся повторов.
4. `scheduler.py` проверяет связь и отправляет личное сообщение в тему, чужое напрямую адресату.
5. Срок, просроченный больше минуты, списывается без отправки; отчёт хранится в SQLite до успешной публикации в теме. Повтор переносится на будущий срок.

## Ответственность и приёмы

| Приём | Где | Назначение |
|---|---|---|
| `asyncio.Event` | `main.py`, `scheduler.py` | Разбудить цикл после команды |
| `ControlTopic` | `control.py` | Одна точка фильтрации и отправки в тему |
| Очередь `notices` | `db.py`, `scheduler.py` | Сохранить отчёт до отправки |
| `scheduled_msg_id` | `db.py`, `scheduler.py`, `commands.py` | Снять старые запланированные сообщения после обновления |

## Риски

- Пока процесс выключен или нет связи, сообщения не могут уходить по сроку; после возвращения сервис сообщает о пропусках.
- Время SQLite не содержит часового пояса; смена часового пояса хоста меняет трактовку сохранённых сроков.
- Неверное/дублирующееся имя группы или темы останавливает запуск с ошибкой.
