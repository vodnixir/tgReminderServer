# Структура проекта

## Верхний уровень

| Путь | Назначение | Основание |
|---|---|---|
| `main.py` | Вход, обработчик команд, контроль фоновой задачи | `main.py` |
| `control.py` | Поиск группы и темы, фильтрация и отправка в тему | `control.py` |
| `commands.py` | Разбор команд, проверка адресата, список и удаление | `commands.py` |
| `scheduler.py` | Отправка по сроку, пропуски, связь и отчёты | `scheduler.py` |
| `db.py` | SQLite, миграция, переход повторов и очередь отчётов | `db.py` |
| `config.py` | Переменные окружения и локальные пути | `config.py` |
| `tests/` | Проверки парсера, темы и расписания | `tests/test_commands.py`, `tests/test_control.py`, `tests/test_scheduler.py` |
| `deploy/` | Пример unit-файла systemd | `deploy/tgreminder.service` |

## Точки входа

- `python main.py` вызывает `asyncio.run(main())`.
- `main.py` создаёт `scheduler_loop` как задачу asyncio и перезапускает процесс через systemd при её аварийном завершении.
- Отдельного worker или CLI нет.

## Границы модулей

| Модуль | Ответственность | Связь с другими |
|---|---|---|
| `control.py` | Конкретная группа и тема | Используется в `main.py` и `scheduler.py` |
| `commands.py` | Преобразование текста в напоминание | Вызывает `db.py` и Telethon для проверки адресата |
| `scheduler.py` | Выбор срока, отправка, отчёты | Вызывает `db.py`, Telethon и `control.py` |
| `db.py` | SQL и расчёт следующего срока | Не зависит от Telegram |

## Имена и организация

- Исходники лежат в корне; модули и функции названы в `snake_case`.
- Импорты используют имена модулей корня; пакетных алиасов нет.
- `.env`, `.session`, база и виртуальные окружения исключены через `.gitignore`.
